# 飞牛影视服务管理插件

当前公开版本为 `0.1.1`，最低宿主版本为 `0.3.6`，使用 API v2 和固定 `fntv.service` 能力。在应用中心刷新公开目录后可以直接安装；也可下载 [fntv-0.1.1.tgapp](https://raw.githubusercontent.com/lengyuesky/tgdrive-app/main/apps/fntv-0.1.1.tgapp) 导入。

安装包提供中文服务管理页，后台协议由宿主的受限能力执行。先在应用中心安装，选择允许读取的网盘目录，再保存独立影视账号、创建命名的电影库或电视剧库，最后主动启动服务。官方客户端手动添加页面显示的服务根地址，不添加 `/fntv` 前缀。

从本地候选 `0.1.0` 升级保留影视账号、媒体库、观看记录和运行状态。成功更新会废止旧登录并中断旧传输，已有客户端需重新登录；原来停止的服务仍需主动启动。最低宿主提高到 0.3.6，以包含官方客户端媒体库、整数秒续播和季页首集起播的兼容修复。

关闭管理页后服务继续运行。停止、撤权、更换凭据、成功更新、停用或卸载会废止旧登录并中断相关传输。卸载默认保留服务数据，原网盘文件始终由宿主管理。该服务与 `cinema` 的库、收藏及进度独立，首期单用户。

视频按原字节及 HTTP Range 传输；首期根据文件名、目录和同目录 NFO、海报组织内容。媒体描述使用宿主的受限 FFprobe，读取后端须支持 MTProto 分段或已有的允许目录内本地缓存。解析失败会明确报告，不转码、不重封装、不完整缓存视频，也不联网刮削。

## 本地构建

使用 Node.js 22.22.0，在本仓库执行：

```sh
npm ci
FNTV_PACKAGE_OUTPUT=/path/to/local-output
npm run build:fntv -- "$FNTV_PACKAGE_OUTPUT"
```

独立命令只生成指定目录中的 `fntv-0.1.1.tgapp`，不更新公开目录资产。完整 `npm run build` 则生成四款正式包及 `catalog.json`、`SHA256SUMS`，共用同一飞牛插件构建入口。页面依赖 SDK 声明的 `fntv.service` 能力，不能仅凭 SDK 函数存在判断宿主支持。

完整隔离宿主已在 2026-11-06 通过指定官方飞牛播放器 1.12.3 在 Mac 兼容运行路径下的 MP4 解码、暂停恢复、拖回与续播、MKV 双音轨实际声音输出、外挂 SRT 渲染、电视剧库和季页首集起播。该原生验收使用 0.1.0 候选包；0.1.1 没有改变页面或 SDK 运行逻辑，公开目录安装及升级另按 [发布验收记录](../docs/fntv-0.1.1-release.md)验证。其他设备、HTTPS、4K/HDR、内嵌字幕和未列出的播放组合分别验收。
