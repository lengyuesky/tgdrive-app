# 代码贡献指南

欢迎参与 `tgdrive-app` 插件与扩展工具链的开发与维护！

## 参与前提

- **Node.js**：`>= 22.22.0`
- **npm**：`>= 10.0.0`

> **注意**：宿主仓库 `tgdrive` 为私有仓库，但外部贡献者**无需**任何私有仓库权限，即可在本仓库中独立运行所有静态检查、编译构建与单元测试。

## 开发规范与约定

1. **类型安全与严格模式**：
   - 必须保持 TypeScript `strict: true`，提交前必须通过 `npm run typecheck`。
   - 避免使用 `any`，为核心模型与消息通信补充精确类型。
2. **代码风格与注释**：
   - 所有新增代码注释与文档说明使用**中文**。
   - 遵循现有的无分号、单引号、函数式模块化代码风格。
3. **零外部网络依赖**：
   - 插件必须能够在完全离线的沙箱环境中正常运行。
   - 严禁在页面或打包产物中引入外部 CDN 脚本、远程字体或跟踪器。第三方依赖包随 `.tgapp` 打包分发，并包含对应开源许可证。
4. **包体积限制**：
   - 单个 `.tgapp` 压缩后不得超过 16 MiB，解压后不得超过 32 MiB，单个资源文件不得超过 8 MiB。
5. **单一概念单一拼写**：
   - 保持架构概念一致，如 `manifest`、`catalog`、`digest`、`tgapp` 等。

## 阅读馆与分发边界

官方仅发布 `shorts`、`reader`、`cinema`。`reader` 1.0.0 最低宿主 0.3.3；`books`、`comics` 的解析器源码和回归继续维护，但不再单独进入 catalog 或 apps。浏览器集成使用 reader 应用 ID，内容种类仍按实际格式区分。

第三方许可、ZIP、DOMPurify、PDF worker、cmaps 和标准字体必须随阅读馆一起分发。修改公共 SDK 后需比较其他插件摘要；同版本产物变化必须升版，不能跳过防篡改。新截图完成前请在新的临时输出目录迭代构建。

## 提交 PR 前的自检清单

在提交 Pull Request 前，请务必在本地依次执行并确保全部通过：

```bash
# 1. 确保类型检查与插件构建无错误
npm run check

# 2. 确保所有独立单元测试与目录防篡改测试通过
npm test

# 3. 确保根目录分发清单与本地包核验通过
npm run catalog verify ./catalog.json

# 4. 确保全资产校验和通过
sha256sum -c SHA256SUMS
```

## 发现 Bug 或安全问题

如果发现关于插件沙箱逃逸、XSS 漏洞或权限绕过的问题，请不要公开发布 Issue，请直接联系维护者进行私下协调修复。
