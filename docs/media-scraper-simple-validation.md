# 影视刮削 0.1.1：目录一键刮削验收

日期：2026-11-14。用户确认“选择目录后点击开始，完成整个目录刮削；不确定的直接跳过；不在后台进行”。本版主流程已按此简化，目录递归、全部分页、资料检查及执行由页面连续完成。

本文为 0.1.1 的历史记录。该版本错误地将同番号的多个来源列为跳过条件，导致 SONE-614 等标准命名影片无法刮削；0.1.2 已改为同号多来源自动尝试，见 [修复验收记录](media-scraper-0.1.2-validation.md)。下文旧测试通过仅说明符合当时的断言，不代表旧规则合理。

## 行为与范围

- 不再要求选片、点击预览、选择候选或再次确认执行。唯一授权目录可直接带入，打开页面本身不会开始刮削。
- 唯一的番号精确匹配自动采用；多个精确来源、无法识别、无匹配、文件冲突及资料归属不明确时跳过，继续处理其他视频。
- 主页面只保留目录、开始／停止、进度和结果。后端连接、目录授权和覆盖选项位于设置，默认补齐 NFO 与海报。退出覆盖模式后，隐藏的单项选项不会阻止默认补缺。
- 先读完整个目录快照，再开始移动与写入，防止文件移动影响尚未读取的分页。同基本名的不同后缀自动成组，共用资料只写一份。
- 扫描、匹配、启动及写入期间均可停止。不可中止的创建／启动请求返回后先收尾；在途写入先取得宿主停止回执，再关闭响应。关闭或重新打开页面不会自动续跑。
- 未完成项可一键重试，先自动核实普通中断，再读取当前文件并按补缺模式执行。恢复记录仅供查看；存储结果不确定和服务中断继续使用宿主原有保护。

本版仅修改影视刮削页面和相关验证、分发文档，继续使用原有 SDK 与宿主接口，最低宿主保持 0.3.10。

完整 E2E 显式启用 `TGDRIVE_SCRAPER_PUBLIC_BACKEND=1`、`TGDRIVE_CAPTURE_SCREENSHOTS=1`，并通过五个 `TGDRIVE_READER_PREVIOUS_*` 变量提供阅读馆 1.0.1–1.0.5 的真实历史包。历史包与各自 Git 提交的目录摘要核验一致，完整运行包含全部旧包升级及截图用例。

其中七项刮削 E2E 验证：

1. 选择目录后一次开始完成三个视频，默认补齐 NFO／海报，字幕同行；真实 Cinema 页面显示标题、年份、完整长简介和海报并播放，FNTV 协议读取相同资料。
2. 一次开始扫描 105 个视频，跨过 100 条分页边界：子目录两条视频成功，另外 103 条因无法识别或匹配不唯一跳过。多来源候选使用受控 RPC 响应；跳过的视频保留原位置。
3. 取消真实在途写入后，点击一次重试即可自动核实并补齐资料。
4. 关闭真实应用页面会停止批次，重新打开保留目录入口但不自行续跑。
5. 海报服务故障时保留已写入 NFO，手动重试后只补齐海报，NFO 内容版本保持一致。
6. 指定公共 MetaTube 后端通过真实网络请求，为合成视频写入符合预算的 NFO 和 JPEG。
7. 备份恢复所得记录只供查看，手动重新开始后创建新任务。

首轮专项验收的两个取消／恢复用例暴露了停止回执的时序问题。修复为宿主确认停止后才中止在途步骤请求，并让测试在宿主进入停止状态后释放受控上传；原断言保留。修复后七项专项全部通过，最终 81 项完整回归再次全部通过。新增的 14 项执行器单测还覆盖迟到的创建／启动响应、扫描和匹配中关闭、跨组资料冲突及重复分页游标。

命令与报告保存在本机 `.build/scraper-simple-20261114/`：五步门禁为 `final-gates/report.json`，完整回归为 `e2e-final/report.json`，分发一致性为 `package-verification.json`。这些临时日志不属于公开分发资产。
