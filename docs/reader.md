# 统一阅读馆

当前分发阅读馆为 `reader 1.0.3`，要求宿主 `0.3.3`。官方仅分发 `shorts`、`reader`、`cinema` 三款。书库由用户手动命名并一库绑定一个目录，在对应书库内浏览 TXT、EPUB、PDF、CBZ、ZIP 和图片目录。`books/`、`comics/` 的底层解析器源码和回归保留，独立官方分发入口退役。

## 混合内容与阅读偏好

同一应用按文件真实格式选择文字、PDF 或漫画解析器；作品内容种类仍为 books/comics，不能把这些数据种类批量改为 reader。书库内可按类型、格式、分组和阅读状态筛选；“目录全部文件”只查询当前书库目录及子目录，不聚合其他书库。书签、阅读进度和偏好属于 reader 的应用私有存储。

阅读馆首装无偏好时，文字默认分页、漫画默认单页并适宽、PDF 默认适页；手机进入正文时隐藏工具栏，桌面初始显示悬浮工具栏。已有自定义模式、缩放和作品覆盖继续生效。1.0.1 的 V2 “单页＋整页＋100%”默认组合会以原修订号 CAS 迁移一次为适宽，保存 `comicWidthDefault: 1` 防止之后用户主动选择整页又被修改；其他格式和作品记录不变，冲突不自动覆盖。旧 flat/V1 仍只在内存映射。原 books/comics 的滚动回归继续通过显式偏好或独立解析器夹具保留。

## 手动目录书库与铺满宽度（1.0.2）

- 首页和“全部书库”只显示用户创建的书库；不自动生成图书、漫画或格式分类书库，不采用旧来源，也不把宿主目录授权当成书库。
- “创建书库”需填写名称并绑定一个目录，确认后立即扫描该目录及子目录，将独立索引保存到 `library:cache:shelves:v1:index:source:<nodeId>`；配置保存在 `library:shelves:v1`。创建前不枚举或显示网盘图书，从文件打开也不会自动创建父目录书库。
- 点击书库只显示对应目录的图书与漫画，切换会重置旧搜索、状态、分页和滚动位置。每库最多 2000 项整理索引，切换只驻留一份；超过上限可使用“目录全部文件”进行同目录的宿主分页查询。
- 最多 16 个书库，名称和绑定目录均不可重复；根目录另需确认。书库管理支持改名、重新扫描与删除绑定，删除不清除网盘文件、进度或书签。
- 重开应用先显示书库列表，不自动扫全盘；进入书库复用可用索引，显式刷新及相关文件事件只扫描当前目录。目录身份核对不依赖 JSON 键顺序，避免缓存被误判失效。
- 手机点左上角菜单打开同一书库侧栏，支持关闭按钮、遮罩、ESC 和 Tab 焦点循环；抽屉打开时背景不可操作。
- 漫画内边距为零，菜单悬浮且显隐不改变正文尺寸；桌面和手机通过宿主声明的 `ui.setImmersive` 请求全屏，返回书库恢复宿主界面。
- 默认等比例铺满视口宽度，小图也会放大；高图不因屏高缩小，超出的高度可上下滚动。手动选择整页时保持完整画面及必要空白；不拉伸、不裁剪，两轴共同受 CSS 尺寸上限约束。

手动目录书库与适宽行为的 1.0.2 验收见 [1.0.2 发布验收记录](reader-1.0.2-release.md)。[1.0.1 发布验收](reader-1.0.1-release.md)、[全屏与侧栏独立验证](reader-layout-validation.md) 和 [1.0.0 集成验证](reader-validation.md) 保留为历史记录。

## 书库紧凑布局（1.0.3）

- 手机端默认收起内容类型、格式、阅读状态、排序与分组筛选，点“筛选与分组”展开；非默认条件显示数量，收起不会清除条件。
- “重置筛选”清除类型、格式、状态、分组和排序，但保留当前手动书库及搜索词，不扩展到其他目录。
- 管理分组和“目录全部文件”位于展开面板；作品/文件切换始终可用。“批量分组”收起面板并显示独立移动栏，退出后恢复紧凑布局；只展开或收起面板不清空已选书籍。
- 书库名称与目录路径合并为紧凑标题区；手机顶栏使用有无障碍名称的设置、返回图标，点击区域仍不少于 44px。桌面筛选直接显示，改变视口时同步切换布局。

从 1.0.2 升级保留已有手动书库、分组、阅读进度、书签与自定义偏好，不要求重新创建书库。本版四张正式截图、真实旧包升级与完整本机集成结果见 [1.0.3 发布验收记录](reader-1.0.3-release.md)；升版前的独立验证保留于 [紧凑布局验证](reader-compact-layout-validation.md)。

## 旧应用替换与清理

宿主 0.3.3 的安装预览会列出阅读馆替换的已安装旧图书/漫画应用，并说明应用私有数据清理范围。确认替换后，旧应用的进度、书签、偏好、书库配置及恢复快照会清理，不会自动迁移至 reader。网盘原文件及网盘收藏继续保留；取消安装不会执行替换或清理。需要替换的应用必须单独确认，普通批量更新不承担这一清理动作。

安装前请保留自己需要的旧进度与书签记录；确认后在阅读馆手动创建书库并绑定目录。仅从 catalog 移除旧包不等于旧应用数据已经迁移，不能把保留解析器源码描述成跨 ID 无损升级。

已经安装 `reader 1.0.2` 的用户更新到 `1.0.3` 会保留当前手动书库及分组，无需重建。安装 `reader 1.0.0/1.0.1` 的用户也可直接更新到 `1.0.3`；同 ID 更新保留应用记录，但旧 `library:sources` 不会成为手动书库。真实 1.0.1 升级验收中，用户重建同目录书库后旧进度和书签继续可用；自定义偏好保留，仅上述旧默认组合迁移为适宽。这与首次替换 `books`、`comics` 的清理行为不同。

## 构建与验证

`build.mjs` 仅构建 shorts、reader、cinema。reader 包同时携带 ZIP、DOMPurify、PDF worker、cmaps、standard_fonts，以及 ZIP/DOMPurify/PDF.js/core-js 和字体许可、NOTICE。不得依赖旧 books/comics 安装包或远程 CDN。SDK 改动若改变其他插件归档摘要，必须按同版本不可变规则检查并协调升版。

`npm test -- tests/unit` 验证三款分发、reader 清单版本、资源许可、退役包清理和同版本防篡改；所有分发构建使用合成临时输出，不依赖根目录已有 reader 包。`npm run test:readers` 使用真实 reader 入口与内存 Drive，保留书/漫内容夹具，新增 390/1280 两视口混合阅读切换。`npm run test:comics` 继续直接回归底层漫画几何与滚动。

跨库用例位于 `tests/browser/`，通过 reader 应用 ID 验证同库全部格式、移动阅读、来源、全库索引和平台集成。仅用显式 `TGDRIVE_HOST_DIR` 指向获授权宿主，使用临时数据库、内存 Telegram 与合成媒体；同一时刻只能有一个服务占用 4187。Cargo 默认复用该宿主的 target 目录。截图只写测试产物，最终源码截图由维护者独立生成。

每次迭代构建使用新的空 `TGDRIVE_APP_BUILD_OUTPUT`；真实截图完成后才生成最终根目录分发资产，不清除已发布基线绕过保护。`compatibility.json` 的 host_ref 记录宿主 0.3.3 的实际验证提交，Git tree 与已通过本地验收的工作区一致。后续若验证未提交改动，须另外记录真实 base SHA、dirty 状态和验证范围。当前版本的命令、最终结果、未执行项与限制见 [1.0.3 发布验收记录](reader-1.0.3-release.md)。
