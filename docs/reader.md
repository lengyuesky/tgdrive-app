# 阅读馆 2.0.0

阅读馆保持应用 ID `reader`，采用契约 1.0 的纯页面结构，包目标为 `web`，没有应用后端，只声明网盘只读访问。页面使用 `@tgdrive/page-sdk` 直接调用宿主，界面资源来自 `@tgdrive/ui`。不使用旧 SDK、宿主应用设置、网盘收藏或宿主数据迁移回调，不迁移旧平台记录。

## 页面与阅读功能

入口为 `reader/page/index.html` 和 `reader/page/main.ts`；应用外壳在 `reader/app.ts`，数据层在 `reader/library/`，格式解析器完整保留在 `reader/formats/`。

- 首页和“全部书库”显示用户手动创建的命名书库；每库绑定一个目录 ID，最多 16 个。授权目录不会自动成为书库，选择目录也不等于授予读取权限。
- 同一书库支持 TXT、EPUB、PDF、CBZ、ZIP 和直接含有图片的目录。重命名或移动书库目录仍跟随 ID；同路径重建的新目录不会接管旧书库。
- 保留作品归组、卷话顺序、番外、人工元数据、图书分组、想读、应用收藏、阅读状态、历史、书签和分格式/作品级偏好。多键更新不伪装成事务，冲突显示失败或保留草稿，重读后由用户确认重试。
- 从文件“打开方式”启动时直接核验并打开该文件或图片目录，不要求先创建书库；仅建立临时阅读来源，不写入书库绑定，也不扫描全盘。
- 首次默认文字分页、漫画单页适宽、PDF 适页；保留翻页、长条漫滚动、物理单双页、缩放、正文搜索、层级目录和按需缩略图等阅读行为。
- 沉浸、标题、选目录、请求授权、扫描进度/取消、主题和关闭前保存使用 `tgdrive.ui.v1`。关闭前保存尊重宿主给出的期限；浏览器强制退出不保证最后一笔保存。

## 文件发现与增量核对

`library/discovery.ts` 将两路宿主通用索引按名称或时间归并：

1. `files.query` 按支持的后缀集合、字面文件名和排序分页。
2. `files.directories_with_files` 查询直接含有指定图片后缀文件的目录，不把仅在子孙中含图片的父目录当作图片章节。

双路游标是应用自己的位置对象，分别保存宿主游标、页内已消费数量与结束状态；不解码或改写宿主游标。普通分页只以 `next_cursor = null` 结束，不以页内数量判断结束，也没有旧的 2000 项书库截断。扫描只收集阅读单元，不递归枚举其他类型的完整文件树；完整扫描保存第一页 `scan_cursor`，结束后消费变更接口，以 `has_more` 判断本轮高水位。

增量核对处理新增、覆盖、改名、回收、图片移动和后缀改变；子树失效只重查受影响子树。授权变化或日志过期重新读取授权并完整核对。失败或取消的扫描不把未核实的旧项当成已删除；撤权立即清除可见派生列表。SSE 只提示同步，不是持久日志或写入回执。

“目录全部文件”提供同一书库的独立键集分页和浏览位置保存，不要求先完成整理索引。它只按通用属性筛选；作者、作品分组和阅读状态筛选属于已整理的应用索引。

## 应用 KV 键设计

| 键 | 用途 |
|---|---|
| `reader:data-version` | 当前应用数据布局版本 1；未知版本拒绝启动，不覆盖。 |
| `library:shelves:v1` | 命名书库、绑定目录 ID、显示路径、根目录确认与配置修订。 |
| `library:cache:shelves:v1:index:source:<目录ID>` | 每书库独立的阅读单元索引指针，元信息含来源身份、根信息、完整性和变更检查点。 |
| `library:works` | 作品、成员、顺序、人工元数据和合并别名的快照指针。 |
| `library:book-groups` | 图书分组快照指针。 |
| `progress:<节点ID>` | 当前文件信息、标题和语义阅读位置；不把排版页数当作字符位置。 |
| `bookmark:<节点ID>:<随机ID>` | 书签名称、位置和文件/图片目录版本。 |
| `library:reading:<节点ID>` | 绑定版本的显式未读/在读/已读状态。 |
| `library:flags:<作品ID>` | 想读与应用收藏，彼此独立。 |
| `preferences`、`preferences:work:<作品ID>` | 分格式偏好与作品稀疏覆盖，记录结构版本为 2。 |
| `reader-ui` | 常驻章节与进度等界面偏好。 |
| `reader:browse:v1[:source:<目录ID>]` | 双路查询、页码和当前浏览位置，条件保存；失效游标不会静默跳页。 |
| `library:cache:history` | 最近 2000 条阅读历史的时间排序索引，不删除原始进度；每笔确认保存的进度更新此索引。 |
| `library:cache:metadata:<摘要>` | 应用自己的可再生元数据缓存，4 MiB 热点预算。 |

快照键使用 `<指针键>:shard:<随机快照ID>:<分片序号>` 存不可变行分片；分片目录过大时再使用 `:index:<快照ID>:<序号>`。单值遵守 32 KiB，默认行分片预算 24 KiB。先条件新建全部分片，最后对单一指针 CAS 发布；明确失败只清理本次草稿，确认成功后回收被替换分片。发布结果未知时保留分片，重读核实，不删除可能已经生效的数据。

## 字节、封面和资源边界

解析使用 SDK Range 读取与有界分块缓存；传输排队、退避和会话续签均由 SDK 承担，应用不再叠加请求队列。TXT 上限 64 MiB，EPUB/PDF 512 MiB，漫画归档 2 GiB；归档/图片章节最多 10000 项，超限明确失败，不冒充完整内容。图片在解码前核对格式与 3200 万像素上限，正文图片窗口与 PDF 画布另有预算。

封面小图写入通用 `cache.objects`，键为 `unit:<节点ID>`，随 `sources` 附上实际参与生成的原文件/封面图片内容引用。目录本身不是内容引用。命中和生成后仍核对目录归属，源覆盖或撤权后由宿主自动失效。媒体与缓存票据是以 `/` 开头的同源相对路径，页面直接用于 `fetch`、图片或下载，不假设它们是绝对 URL。

包内携带 ZIP、DOMPurify、PDF.js legacy 主模块与同版 worker、cMaps、标准字体及全部第三方原始许可；运行时不使用 CDN。第一方遵照主分支已声明的 MIT 许可，随包复制已有根 LICENSE，不在应用代码中另加许可头。

## 相对旧版移除的功能

- 移除“在文件中显示”及网盘定位按钮，界面通道不提供此能力。
- 不再打开宿主文件详情；保留应用内以当前 `FileNode` 显示路径、节点 ID 和大小的文件信息。
- 不再调用旧宿主设置、网盘收藏、旧数据迁移和批量 RPC；这些业务改为应用自己的 KV、设置界面和条件写入。

## 构建、测试和真实宿主待确认项

```bash
fnm use 22.22.0
npm ci
npm run typecheck
npm test
npm run contract:check
node tools-v1/build-pages.mjs reader "$NEW_OUTPUT"
# 独立真实浏览器回归，不连接宿主。
npm run test:formats:browser
npm run test:pictures:browser
```

`NEW_OUTPUT` 必须是仓库外且尚未创建的目录。构建实际调用 `tgapp pack` 和 `tgapp verify`；包只在同仓库 GitHub Release，目录与发布历史同一提交保存在 main，不在 main 保存安装包或全局摘要文件。升版与手动发布见 [应用开发指南「CI 与发布」](app-development.md#8-ci-与发布)。具体包大小、摘要、重复构建与全部门禁结果以本次交接报告为准。

单测保留格式、阅读几何、界面、范围、书签、偏好与并发回归，并使用 `@tgdrive/test-host` 验证通用查询、至少一万个长路径文件的字节截页、扫描期间变更、子树/图片增量核对和 KV 发布冲突。旧批量 RPC、旧迁移、旧可选封面能力的用例分别改测并行 stat、不迁移/不覆盖、必备小对象缓存失败降级。旧默认组合迁移 CAS/迁移标记取消专用用例不再保留，因为新平台明确不执行迁移；普通偏好 CAS、配额、取消与草稿恢复矩阵继续覆盖对应失败边界。旧宿主全库视图测试重命名为应用自己的通用双路分页测试，没有删除其分页、来源越界、迟到结果和条件保存覆盖。

独立真实 Chromium 回归保留 11 项漫画阅读器几何/滚轮/触摸/惯性/异步尺寸校验和两个图片窗口视口用例；采用当前 `HostClient` 与合成数据，不连接宿主。不能将它们称为整个阅读馆应用的浏览器验收；TXT/EPUB/PDF 和书库管理目前主要由单测覆盖，旧全应用全局 SDK 浏览器夹具已删除。

本次不包含真实浏览器对接宿主的端到端验收。联调仍须确认沙箱/CORS/CSP、相对票据 URL、PDF/ZIP 随包资源、长名称标题、真实 Telegram Range 与取消、授权变化、票据过期、关闭保存期限、主题和手机触摸/旋转表现。旧验收记录不证明新平台已在真实宿主通过。
