# 第 1 阶段：只读 SDK 请求调度

发布版本：短视频 1.4.5、图书 1.6.6、漫画 1.4.6、影视 1.4.4。

## 行为

- 每页面最多四个在途只读 RPC，后台最多两个。封面缓存读取、统计与缩略图票据默认后台；其他读取默认前台。
- `CallOptions.priority` 支持显式前台或后台。短视频下一条播放地址预取使用后台队列。
- 连续八个前台请求后给后台一次调度机会；队列最多 128 项，每项最多等待 30 秒。队列满返回 `sdk_queue_full`，不自动重试。
- 排队取消不发送 RPC；页面关闭拒绝排队、在途及退避请求。在途结束或失败释放槽位，退避不占槽。
- 原有限流等待下限 250、750、2000、7000 毫秒增加 0～25% 抖动，仍最多四次，仅重试宿主明确限流的只读调用。
- 写入、混合批量信封、生命周期和 UI 调用不排队；票据 URL 的直接网络读取不受 SDK RPC 调度控制。
- 没有合并相同请求，避免改变读取时序和独立取消语义；没有放宽宿主权限与限流。

## 实际验证

Node.js 固定为 22.22.0。真实沙箱测试使用当前宿主提交 `ac6128799936d52c21d0d2e0d62463b37851386e`，Rust 1.99.0，临时数据库、内存 Telegram 与合成媒体。没有读取生产环境文件或真实网盘文件。

| `npm ci` | 退出 0；审计提示 1 个低危、2 个中危依赖问题，未自动强制升级 |
| `npm run check` | 退出 0，类型检查和四款最终包构建通过 |

首轮全量单元测试发现发布文档示例未同步新清单，修正文档后重跑全部测试通过，没有绕过校验。新增单元覆盖并发上限、前台保留、后台公平性、队列容量/超时、取消/关闭、发送失败释放槽位及退避抖动。

没有执行手机真机验收、长期内存压测或吞吐基准，不能据此宣称已测得速度提升。SDK 更新通过独立应用包分发，已安装实例需在应用中心更新；重建宿主容器不会覆盖已安装应用或应用数据。后续阶段为主项目性能指标、扫描恢复与索引分页、真机和弱网回归、部署回退、基于测量的缓存与模块优化。
