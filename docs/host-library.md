# 第 3 阶段：宿主全库文件索引

图书 1.6.7、漫画 1.4.7 新增“书库 → 全库”，使用宿主 `library.page` 能力。短视频 1.4.6、影视 1.4.5 同步公共 SDK，现有播放行为不变。

## 使用与边界

- 查询已添加来源下的全部子目录，图书支持 TXT/EPUB/PDF，漫画支持 CBZ/ZIP 和直属图片目录。
- 当前页 40 项，文件名与格式筛选、文件名或文件创建时间排序。旧的 2000 项整理上限不影响这个入口。
- 索引在宿主 SQLite 中自动维护，不需要在 App 保持后台扫描任务，也没有跨会话扫描断点丢失问题。
- 浏览位置以一条 CAS 记录保存，重开恢复筛选、页号和游标；每次必须通过宿主修订及目录权限校验。跨会话不恢复整条前页历史，当前会话前页历史最多 100 条。
- 文件或权限变更清除旧卡片。旧游标返回 `reading_index_changed` 时需从首页刷新，不静默跳过新增文件。全局修订较保守，无关目录变动也可能要求刷新。
- 没有把作者、作品分组、阅读状态或正文搜索宣称为全库索引。这些能力仍在原“作品/文件”视图内，受已整理范围限制。全库卡片不把未知阅读进度标成“未读”。
- 旧宿主没有声明 `library.page` 时不显示新入口，原有阅读馆仍可用。

## 部署状态

本轮两次 `docker compose build tgdrive` 均退出 1：第一次 `gcr.io` 的 distroless 元数据请求返回 503，第二次 Docker Hub 的 Node 镜像元数据请求返回 503。构建未完成，没有执行后续新容器替换，也没有清理可能仍需使用的旧镜像。现有容器保持 running/healthy，运行的是已部署的第 2 阶段版本，不包含本轮全库入口。

App 包可独立更新；当前生产宿主会安全隐藏“全库”入口。需在镜像源恢复后成功构建并部署新宿主，才能启用该入口。没有将重建旧容器作为新版本部署证据。

未执行实体手机、十万级文件负载或长时间内存压测；新增手机验收是浏览器模拟视口，不是手机真机。
