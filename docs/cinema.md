# 影视应用

「影视」是独立应用（`cinema 1.0.7`，应用契约 1.0），同时提供网页播放器和飞牛影视兼容服务。在应用中心安装后打开，先创建命名媒体库并绑定文件夹，再进入该库查看视频。它不替换短视频，也不改变文件页的视频预览。

## 同番号影片的条目与版本（1.0.7）

本节取代原设计 Q21/Q41 中「同番号视频各自独立播放入口」的决定：影片条目与媒体文件分开，同一影片的版本和分段不再各占一张电影卡片。

- **归组范围**：仅电影库。只有同一个媒体库、同一个父目录节点下，NFO 的 `<num>` 或 `<uniqueid type="number">` 含相同非空番号的视频才合并；比较时去首尾空白并忽略大小写。空 `<num>` 可继续采用非空的番号 `uniqueid`。不同目录、不同媒体库、没有有效 NFO／番号及电视剧库均不按番号合并，不凭视频文件名猜测归组。
- **持久身份**：番号电影条目 GUID 由「媒体库 ID＋父目录节点 ID＋规范化番号」散列产生，即使暂时只有一个版本也采用这个身份。增删版本或更换代表文件不会改变条目 GUID。每个文件的 `media_guid` 仍由节点 ID＋内容版本产生；替换文件内容不复用旧版本的进度、轨道或探测结果。
- **代表资料**：文件名采用稳定自然排序，原名和节点身份破同值，取第一个文件作为代表。影片标题去掉末尾版本标签，海报、完整简介、年份和演员采用代表文件的资料；增加更早排序的文件或删除代表文件时，可换代表而不换条目身份。
- **版本名称与顺序**：优先使用 NFO 标题末尾非空方括号内的标签，如「4K 中字」「1080P 第1段」「1080P 第2段」；没有标签时使用去扩展名的原文件名。标签按自然数字排序，再按文件名和节点身份稳定破同值，第 1、2、10 段按段号相邻排列。
- **网页交互**：库内网格、目录浏览和同目录合集都只展示一个影片条目。详情与播放器提供版本选择，切换时先保存并关闭旧文件的播放会话，再播放所选文件；恢复位置、字幕和音轨只读取该文件的记录。直接点击首页播放也遵守默认版本规则。
- **默认与历史**：默认采用当前条目内最近保存过播放记录的文件；时间同值时按稳定文件名顺序取舍。没有播放记录则选代表文件。已播完的最近版本仍是默认版本，但从头播放。最近播放、观看历史与继续观看每个影片条目只出现一次；收藏和手动已看标记属于条目，文件的完成状态和进度分别保存。
- **分段**：每一段都是独立可选版本，不拼接，不自动连播，不通过相邻文件查询跳到下一段；电视剧原有选集和连播不变。
- **应用数据版本**：私有 SQLite 的 `user_version` 从 1 升到 2。不兼容旧结构，不做迁移，首次打开旧数据库直接重建全部影视应用数据，包括旧索引、媒体库配置、连接账号和观看状态；需要重新配置媒体库与飞牛连接账号。网盘中的视频、NFO、字幕和海报不修改。相同数据版本的普通重启仍保留业务数据。

### 飞牛多文件协议与证据边界

`GET /v/api/v1/stream/list/{item_guid}` 返回整个条目的 `files`，文件 `guid` 等于自己的 `media_guid`；`video_streams`、`audio_streams`、`subtitle_streams` 仍是平铺数组，每一项携带所属文件的 `media_guid`。`play/info`、`stream`、`play/play`、`play/record` 用请求中的 `media_guid` 选择文件；同时给出 `item_guid` 时核对文件确实属于该条目，错误或已删除的版本不静默回退。只给 `item_guid` 的 `play/info` 与 item 详情采用上面的默认版本，默认媒体身份与代表资料分开。

公开只读依据固定到 `FNOSP/FlyNarwhal` 的提交 `f39566ddb53530ceaa74d5d1220fc8dc4bf63db3`：

- [媒体详情模型](https://github.com/FNOSP/FlyNarwhal/blob/f39566ddb53530ceaa74d5d1220fc8dc4bf63db3/lib/data/models/movie_detail_models.dart#L203-L493) 定义 `files` 列表与三类流的 `media_guid`。
- [详情选择实现](https://github.com/FNOSP/FlyNarwhal/blob/f39566ddb53530ceaa74d5d1220fc8dc4bf63db3/lib/ui/features/movie_detail/movie_detail_screen.dart#L189-L287) 从 `play/info.media_guid` 恢复默认文件，按 `media_guid` 筛选音轨和字幕，并用 `files[].guid` 定位文件；版本切换见该文件第 581–590 行。
- [播放请求实现](https://github.com/FNOSP/FlyNarwhal/blob/f39566ddb53530ceaa74d5d1220fc8dc4bf63db3/lib/ui/features/player/services/player_service.dart#L18-L40) 把所选 `media_guid` 传给 `play/info` 与 `stream`。本地获授权的旧官方 iOS 请求记录也有先只带 `item_guid`、再带 `media_guid` 请求 `play/info` 的顺序，但不是官方多文件服务端响应样本。

**没有官方客户端实测。** 本地旧响应样本均为单文件，不能据此宣称官方多版本界面已验收。未证实独立的 NFO 版本标签协议字段，因此 `files[].file_name` 保留真实文件名，不编造版本名字段，也不把标签伪装成分辨率。公开客户端的选择按钮使用 `resolution_type` 与 `color_range_type`，官方客户端是否显示 NFO 标签、同画质分段如何区分文字仍需实测；现有 item `media_stream.color_range_type` 的聚合类型也未在官方多文件响应中核对。上述不确定性不作为已验证能力。

## 拆分前 iPhone 主屏幕界面设计记录（1.5.0）

以 iPhone「添加到主屏幕」独立窗口竖屏为首要目标，iPad 与桌面沿用侧栏布局，只换新配色。样式基于共享规范 `ui/base.css` 与 `ui/icons.ts`，`cinema/tokens.css` 把旧变量映射到 `--tg-*`。

- **沉浸**：手机（`(max-width: 768px), (pointer: coarse)`）打开即请求宿主 `ui.setImmersive`，并在宿主声明 `ui.immersiveBackground` 时传入当前页面底色；播放时的沉浸与之合并为同一套状态同步（`cinema/shell.ts` 的 `ImmersiveSync`），离开时恢复宿主外壳。安全区由宿主扣除，插件内不使用 `env(safe-area-inset-*)`。
- **配色**：跟随主站深浅色（`context.dark` 与 `theme.changed`），取代原固定深紫主题；播放器区域保持黑底。
- **首页与片库**：顶栏为返回、标题、搜索、媒体库与“更多”；“更多”底部面板含刷新、新建媒体库、媒体库设置、返回网盘。手机去掉营销文案，海报三列紧凑排列，底部四标签为首页、媒体库、收藏、历史。
- **详情**：手机全屏推入，顶部为海报模糊放大的背景；“播放 / 继续观看”为主按钮，从头播放、收藏、下载、在文件中显示、文件信息收为图标行。
- **播放**：iOS 上 `video.webkitEnterFullscreen` 可用时优先使用原生视频全屏，其次 `requestFullscreen`。
- 保留全部元素 id、存储键与数据结构；从 1.4.6 更新不迁移数据。

## NFO 与刮削资料

读取同视频基本名的 NFO，缺少时使用 `movie.nfo`；文件名匹配忽略大小写，跨目录分页仍优先专属资料。单份读取上限为 1 MiB，标题、年份和长简介用于海报卡片、首页大图、详情及播放标题。解析拒绝外部实体和非法 XML，不执行资料中的标记。

详情显示完整简介；同番号的归组、版本选择和逐文件进度以上面的 1.0.7 规则为准。番号电影关闭自动连播及同文件夹的片头片尾跳过，明确剧集行为继续保留。海报来源依次尝试 `基本名-poster.jpg/.jpeg`、基本名海报及 `poster`、`folder`、`cover` 的共用海报，再尝试缩略图和截帧。

新版刮削应用的使用、构建与本地验收范围见[影视刮削说明](../media-scraper/README.md)。

## 媒体库设置

1. 在首页或媒体库页点击「新建媒体库」，填写名称，例如「电影」。
2. 点击「选择文件夹」，选择 `/影视/电影` 等实际目录；一个媒体库绑定一个文件夹，自动包含其子文件夹。
3. 保存后返回媒体库入口；点击「进入媒体库」才加载该库的视频，不遍历其他库。可以分别创建「电影」「电视剧」等多个库。

- 首页只显示库名和绑定路径，不为数量或海报扫描目录；重新打开应用也停留在入口页，不恢复上次库的加载。
- 名称为去除首尾空白后的 1–50 个字符，不允许控制字符和重名。同一目录不能重复绑定，父子目录可以分别建库。最多 32 个库，整份配置最多 32 KiB。
- 必须明确选择文件夹，没有默认绑定目录。显式选择 `/` 时需额外确认“包含整个网盘”，取消确认不会保存。
- 「媒体库设置」支持改名、重新绑定和删除；删除仅移除配置，不删除原文件、收藏或观看历史。删除最后一个库后恢复建库引导。
- 目录按节点 ID 绑定，移动／重命名后继续定位原目录；路径只作显示缓存。删除或不可访问时提示重新选择，不误绑定同名新目录，也不回退根目录。
- 配置使用私有存储和 CAS 修订号；冲突保留表单草稿，读取云端最新配置后需要再次确认保存。读取失败或配置损坏时停止加载并提示重试。
- 不接入旧宿主单目录设置或旧索引。数据结构不兼容时按本应用的数据版本规则直接重建；1.0.7 的重建范围见上文，不能将旧资料中的「升级保留数据」说明用于这次更新。

## 界面与功能

- 默认深色影院界面：媒体库入口、库内大封面和继续观看、收藏和历史；手机底部导航、桌面侧栏、横屏和沉浸播放。
- 文件名搜索和格式筛选只递归搜索当前媒体库，目录浏览仅展示直属节点，上一级不能越过该库根目录。每批最多 200 个节点，按服务器游标翻页，不受旧搜索 2000 项上限限制，不显示伪造的全库排序。
- 详情展示所选版本的原文件名、路径、格式和大小；同目录合集采用稳定自然名称排序，番号电影不把版本平铺成合集条目。选集每批显示 100 项，只按 `next_cursor` 翻页，不截断整个目录；电视剧的跨页相邻集查询仍由后端完成。
- 播放、暂停、进度拖动、前后十秒、音量、0.5–2 倍速、适应／填满画面、上一集／下一集、字幕、音轨、全屏、支持设备上的画中画。MKV 暂停后拖动或切换音轨仍保持暂停。默认同目录顺序连播，结束后五秒倒计时，可取消，不循环；详情尚未整理完成就点击播放，也会继续加载完整选集。
- 空格暂停，左右方向键快进退，上下方向键调整音量，M 静音，F 全屏。仅在播放器焦点区域生效，输入框和按钮自身的键盘操作优先。Tab／Shift+Tab 在播放器控件内循环，不落到背后的片库；退出恢复片库交互与焦点。手机左右区域双击快进退，忽略多指和拖动。
- 全屏按标准全屏、iOS 原生视频全屏、页面沉浸降级；始终保留返回入口。安全区由宿主统一处理。

## 播放格式：转封装不是转码

| 类型 | 行为 |
|---|---|
| MP4/M4V/MOV、WebM、OGV | 优先浏览器原生播放；实际支持取决于容器和编码。可识别的 MP4/MOV/WebM 会在点击播放后检查音视频编码 |
| MKV 的 H.264＋AAC | 客户端解封装并输出分片 MP4，通过 MediaSource 边读边播，支持索引定位和音轨选择 |
| HEVC、VP9、AV1、Opus 等 | 根据实际编码及浏览器 `canPlayType`／`MediaSource.isTypeSupported` 检测，不承诺所有设备可播 |
| AVI、WMV、FLV、TS/M2TS 等 | 会在媒体库显示，可尝试原生播放；首版不提供专门转封装保证 |
| DRM、加密或浏览器不能解码的轨道 | 清楚提示并提供下载，用本机播放器观看；不做重新编码，不自动忽略不支持的音轨 |

媒体模块固定使用 `mediabunny@1.56.1`，随包携带许可证，仅使用纯 JavaScript 容器处理，不访问 CDN，不加载 WASM，不启用 Worker、WebCodecs 编码器或外部网络源。

**不需要服务器 FFmpeg，也没有服务器转码、转码缓存或后台全盘扫描。** 下载入口下载的是原文件，不是浏览器转换后的文件。MKV 转封装需要 MediaSource；部分 iPhone／iOS PWA 的能力与桌面不同，缺少能力时正常降级下载。

### 读取与内存边界

- 媒体库入口页只读取配置；进入库后才查询视频。库内页面和详情不读取原视频，只读取元数据、封面和已有缩略图。点击播放后才签发原视频用途的请求。
- 收藏／历史仅分页读取已有私有记录，以有界 `files.stat` 校验当前路径，不递归搜索目录，也不为凑满一屏翻遍历史；过滤后为空的页仍保留下一页。列表只加载已有缩略图，不枚举父目录找海报。
- 单次 SDK Range 不超过 1 MiB；全应用字节调度最多四并发、每秒八次，为 SDK 控制消息留余量。原生 `<video>` 使用既有签名 Range 媒体地址，不经过这条 JS 字节队列。
- 影片块缓存最多 24 MiB、容器库缓存最多 8 MiB；探测／定位读取预算 16 MiB。不会将整部电影读取为 Blob 或回退整片下载。
- MSE 前方目标缓冲三十秒、后方十秒，移除已播数据；输出写入串行化，单分片和关键帧间累计数据不超过 16 MiB。超限／浏览器配额不足时停止并明确提示。
- 缺少可靠索引的 MKV 不进行整片扫描来提供拖动；从头播放，禁用随机定位并提示限制。
- 切片、拖动重建或退出时取消旧输入／数据泵，暂停并清空播放器 `src`、调用 `load()`，释放对象 URL。失效回调不得覆盖新影片。

## 本地封面与命名

推荐将一部电影或一个季度放入独立目录，例如：

```text
/影视/星际旅程/
  星际旅程 S01E01.mp4
  星际旅程 S01E01.zh.srt
  星际旅程 S01E02.mkv
  poster.jpg
  backdrop.jpg
```

海报优先采用视频同名 JPG/PNG/WebP，再采用同目录 `poster`、`cover`，然后使用网盘已有视频缩略图；横幅优先 `fanart`、`backdrop`。没有图片时显示根据片名生成的渐变占位，不使用外部资料或虚构评分、简介。

卡片图片按视口懒加载；已加载的封面在当前页面保留，滑出再滑回不重复请求，翻页或离开页面才释放图片节点和对象地址。未完成的离屏请求会取消，快速来回滚动不会重复启动同一卡片的加载。会话内仅缓存成功加载的封面，最多 150 项、本地封面字节合计不超过 32 MiB；缓存淘汰不撤销仍在显示的图片地址。

影视后端把封面写入宿主通用 `cache.objects`，随 `sources` 绑定视频；使用同目录海报时还绑定实际采用的海报内容引用。后端依次尝试同目录海报、宿主缩略图和视频截帧；页面只读取已生成的封面，不读取原图或自行截帧。其他设备和会话复用缓存前，后端仍核对当前文件授权、内容版本、海报来源与媒体库范围；索引核对发现替换或新增海报后按当前来源重新生成。收藏和历史也复用这些已有封面，未就绪时保留占位，不另枚举父目录找海报或请求缩略图。

宿主代管的对象缓存每应用为 1 GiB，写满后按最近访问淘汰旧封面，可在宿主应用中心里影视卡片上的「清缓存」按钮清空，不影响收藏、观看进度等业务数据。

目录封面初次从直属节点第一页发现，打开详情整理完整目录后可发现后续封面。建议封面位于独立影视目录，不依赖巨型混合目录的封面自动发现。单张本地封面不超过 8 MiB、1600 万像素，解码前验证尺寸；不执行 SVG。

## 字幕

- 自动发现同目录同名和语言后缀的 SRT、VTT、ASS；默认 UTF-8，可手动切换 GB18030／GBK。
- MKV 内嵌 UTF-8、ASS、SSA 文本轨由有界 EBML 模块按播放窗口提取，支持选择及拖动后的重新定位。
- ASS 仅保留文本、逗号和换行，不还原字体、位置、动画或特效。不执行字幕 HTML，不提取附件字体。
- 字幕开关、大小 14–40、时间偏移 ±10 秒；使用 TextTrack 显示，以兼容原生视频全屏。
- 外挂最多 8 MiB、50000 条。内嵌窗口约为当前位置前十五秒至后四十五秒，最多检查六十四个 Cluster、十万个元素；无索引时不为字幕扫完整片。
- PGS/VobSub 图片字幕及烧录不支持，字幕错误不会阻止正常视频播放。

## 数据保存

只读取宿主授权的文件，不写入网盘；收藏属于影视应用私有数据，不改变网盘的全局收藏。

- 媒体库、索引、账号、收藏、观看状态和偏好保存在影视自己的私有 SQLite 中。后端进度以 `media_guid` 为主键，页面通过 `progress:<文件节点ID>` 读取当前内容版本的进度；收藏通过 `favorite:<条目GUID>` 操作，偏好使用 `preferences`。数据版本为 2，旧结构直接重建，不迁移旧应用数据。
- 收藏和历史只显示所有有效媒体库范围内的视频；库内继续观看只取当前库。文件移出范围、删除媒体库或改绑文件夹只隐藏记录，重新纳入后可恢复显示；无媒体库时不显示视频记录。
- 打开详情、播放、切集、收藏和下载前重新检查文件当前路径，旧记录不能绕过范围限制。番号影片的全局收藏和历史保留条目所属媒体库，不因父子库重叠而切到另一个库的同号条目；其他记录仍进入最深的匹配库。媒体库是影视应用的展示和操作范围，不改变宿主文件权限。
- 跨设备配置在重进页面、刷新及后续播放操作时重新读取，不新增后台轮询。
- 所有设备共用同一网盘实例中的数据。进度在成功读取历史并恢复位置后才保存；播放中最长每五秒保存，暂停、切集和主动退出及时保存。
- 达到 95% 或播放结束标记已看完，再次打开默认从头观看；未完成提供继续观看和从头播放。
- 移动／重命名按节点 ID 更新路径；内容版本改变不复用旧进度；不可访问的记录暂不显示。“清空历史”需要明确确认，包含库外隐藏记录，不删除收藏或媒体库配置。
- 同一文件的进度由后端播放代次仲裁，较旧播放不能覆盖新播放；不同版本分别取得权威。冲突时选择「采用云端」或「保留本次」，不以最大播放秒数覆盖另一设备。读取历史失败时暂不保存，避免覆盖未知记录。
- 偏好冲突读取最新云端值并提示重新调整；不静默覆盖。存储容量不足提示清理历史，不自动删除收藏。
- 主动离开使用宿主最多两秒的退出保存握手；强制关闭浏览器只保证最近一次成功保存，不承诺离线同步。
- 卸载默认保留数据，显式选择清除应用数据才删除媒体库配置、历史、收藏和偏好；原文件始终保留。

### 滚动性能优化（1.2.8）

- 海报解码完成后再挂载；保留滚出视口的已加载图片，回看不重复下载或重建节点。
- 封面库写入改用异步 `toBlob` 编码并串行处理；持续滚动时推迟缩放、编码，停下至少 180 毫秒后处理，退出页面取消队列并释放画布。
- 格式标签使用半透明底色，减少逐卡片背景模糊的绘制开销；悬停动效只在支持鼠标悬停的设备启用。
- 主动进入或切换媒体库时取消旧页面排队的刷新，避免浏览中突然重建列表并回到顶部。

发布只由维护者在 main 手动触发 `release.yml`；CI 重建全部应用，既有同版本包只能逐字节核验后跳过。依赖、工具链、许可或源码改变成包字节时必须升对应应用版本，不重用旧目录或旧安装包作为新平台分发基线，不覆盖既有资产或清空发布历史。
