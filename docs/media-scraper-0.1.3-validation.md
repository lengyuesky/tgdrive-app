# 影视刮削 0.1.3 逐部执行与错误记录验收

日期：2026-11-14。目标版本为 `media-scraper 0.1.3`，最低宿主继续为 `0.3.10`。

## 问题与修复

用户已登录的实际页面为 0.1.2。所查看的一次目录记录有 17 个项目，11 个已经匹配却仍处于等待，另外 6 个只留下“未取得匹配的资料”，整个批次没有完成项。源码先检查整个目录全部影片，再统一 `begin/next`，后面的慢查询会让已匹配影片一直等待。来源错误只存在于页面内存，关闭后无法区分搜索失败、详情失败和无匹配。

0.1.3 在完整扫描后逐个归一化番号执行，同号不同父目录的分组仍使用各自原位置，同号分段及目标别名检查仍在一个单元内完成。每部准备好后立即整理、写入 NFO 和海报，单部确定的失败收尾后继续其他影片；正在提交但结果不明、授权或根目录变化、记录保存不能确认时停止整次任务。

搜索和详情的 HTTP 429、5xx、连接中断及超时最多自动重试一次，有其他同号来源时先尝试其他来源。扫描、来源检查和重试等待均可停止。同号已有步骤提交后固定 provider/id，后续分段重建时不能换源。每批独立管理执行控制器和心跳；收到暂停或完成回执先失效心跳，再保存记录。

目录记录由摘要和最多 24 KiB 的日志页组成，保存文件清单、来源错误、批次及项目标识和终态，不保存可续跑的 owner。文件清单最后写入完成标记及数量；缺页或缺完成标记不能按截断清单重试。写入使用 CAS 和固定写入标识，响应丢失时读回核实；不会取得他人的新 revision 后覆盖。保留 30 天，记录清理不删除网盘文件。

重开记录先触发宿主既有过期租约恢复，再核对实际步骤。部分执行记录过期或不可读时仍展示已保存的目录错误，并禁止按无法核实的记录重试。手动重试先核实中断回执、排除实际已完成视频，再重新读取当前目录内的文件引用。
