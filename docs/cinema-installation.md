# 影视安装与更新

影视使用页面与原生后端，共用媒体库、收藏、已看标记和观看进度。当前应用版本为 `1.0.2`，安装包分别提供 `linux-amd64` 和 `linux-arm64`。

在宿主应用中心安装影视后，打开应用、新建命名媒体库并选择文件夹。主人确认该文件夹的目录授权后保存媒体库。可以分别添加电影库和电视剧库，每个库绑定一个目录并包含其子目录。对外影视服务需要在应用设置中配置独立账号并主动启动。

更新宿主容器不会替换已经安装的影视应用包。应用中心可以直接更新单个应用，或通过「一键更新」刷新目录并更新所有已安装应用，自动沿用原来的包架构。

影视 `1.0.2` 修复升级后出现「游标所属安装已改变」而打不开的故障。更新保留媒体库、目录身份授权、连接账号、收藏、已看标记、观看进度和播放偏好；新后端首次读取时重新核对索引。更高版本的正常升级保留主人已经启动的对外服务状态；同版本重新安装或恢复仍需主人重新启动服务。

## 索引生命周期与回归

宿主文件变更游标绑定安装 generation。数据库绑定新安装时，只撤销旧 `scope_revision` 和 `change_cursor`，不删除业务表；同 generation 的普通重启继续使用有效 checkpoint。完整重建不提交旧游标，持久旧游标收到 `app_changed`、`scope_changed`、`cursor_expired` 或 `invalid_cursor` 后从新 checkpoint 核对。全新 checkpoint 失败则报告错误，不无限重试。

常规后台索引核对与主人页面读取共享同一次核对结果，避免升级启动或服务启动时页面因索引抢锁收到忙碌错误。主人手动重扫仍按显式任务处理。

应用仓库的回归使用合成网盘和私有临时 SQLite，验证更新后文件索引刷新，以及媒体库、账号、服务状态、收藏、已看、观看进度和偏好保留：

```bash
PATH="$HOME/.cargo/bin:$PATH" cargo test --locked -p tgdrive-cinema --test installation
```

宿主集成任务另外使用真实旧包和新包执行应用中心网页升级流程，验证旧 generation 的游标被宿主拒绝、新页面可打开、业务数据保留并回收旧后端。此验证不读取生产配置，不连接真实 Telegram，也不改变真实网盘。
