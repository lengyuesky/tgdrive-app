# 影视刮削

`media-scraper 1.0.0` 使用 TGDrive 应用契约 1.0，由沙箱页面和独立 Rust 应用后端组成。选择获得读写授权的网盘目录后，可整理番号视频并补齐 NFO、精确 2:3 的 JPEG 海报和可用的演员资料。业务状态只保存在应用自己的 `state/app.sqlite3`；页面只负责配置、发出用户命令和查看进度。

## 使用

1. 在应用中心安装与你的 Linux 架构对应的应用包。应用包含页面与后端，只提供 `linux-amd64` 和 `linux-arm64` 两个目标。
2. 在「设置」填写 MetaTube 后端地址和可选 Token，保存后使用。默认地址为 `https://metatube-server.hf.space/`。Token 仅保存于应用后端数据库，页面回读只有「已配置／未配置」；留空保留，勾选清除才会移除。地址允许 HTTP 或 HTTPS，HTTP 不加密，建议使用 HTTPS。
3. 选择目录。选择窗口不会授予权限；开始前由宿主授权窗口请你确认目录及子目录的读写范围。上次使用的可访问目录、从网盘打开的目录可以直接带入，打开应用不会自动开始任务。
4. 点击「开始刮削」。后端先完整扫描并核对增量变化，再逐组处理；前面的影片完成后立即保留，不会等待后续影片的慢查询。页面显示当前视频、视频数、成功／跳过／失败计数，并按页查看结果、文件步骤、演员资料和来源错误。
5. 任务在后端运行，关闭页面不会停止，重开能接上正在进行的任务。同一时间只运行一个任务；点击页面中的「停止刮削」停止后续处理，页面收到宿主任务取消通知时也会发出停止命令。在途写入先收尾或核实，已完成文件保留。

任务期间使用后端活动续期，不需要页面心跳。按需后端空闲后可以被宿主回收；已结束任务的页面不持续轮询并唤醒空闲后端。后端重启、崩溃、宿主重启或恢复后不会自动续跑，旧活动任务会标成中断，由你主动重试。

## 整理和资料

支持 MP4、MKV、M4V、MOV、WebM、OGV、AVI、WMV、FLV、TS、MTS、M2TS、3GP，包含子目录，不按旧分页上限截断。番号从文件名优先识别，文件名没有番号时使用所在目录的唯一番号；普通电影名、画质参数、季集或多个冲突番号不会强行匹配。

散放视频移入当前父目录下的番号目录，已有唯一同番号目录会复用。视频保留原名、节点身份和独立播放入口。同目录同基本名的多种视频格式成组处理；不同基本名、分段和画质版本仍分别保留入口。明确关联的字幕、专属 NFO、海报和本应用头像随视频移动；目录共用或同时关联多部视频的资料不明时跳过，不拆分执行移动，不删除任何文件。

默认保留有效的已有专属或目录共用 NFO、海报，只补缺。设置可分别开启覆盖专属 NFO 和专属海报；NFO 覆盖会整份替换，包括手工编辑内容。目录共用资料不会被删除或原地覆盖，需要时为当前视频新建专属资料。已有资料无法解析、作品归属不符、目标同名或大小写冲突会给出跳过原因。

例如 `ABC-123-4K.mp4` 使用专属的 `ABC-123-4K.nfo` 和 `ABC-123-4K.jpg`。NFO 保留番号、标题、原名、完整简介、发行日期、导演、厂商、品牌、系列、分类、演员、来源，以及来源提供的原始评分。标题显示为「番号 片名」，去掉标题开头重复的同片番号，原名完整保留；不编造缺失信息或未知评分量表。完整 NFO 最大 1 MiB，超过预算拒绝写入，不截断简介。

新海报是精确 2:3 JPEG，最多 1200×1800、2 MiB；头像是精确 2:3 JPEG，最多 240×360、128 KiB。输入图片最多读取 8 MiB、1600 万像素，只接受已启用的 JPEG、PNG、WebP 编解码格式，不处理 SVG、任意文档或外站图片 URL。

只有生成 NFO 时才补充演员，使用当前 MetaTube 后端的唯一精确同名人物。每片人物补充总计最多等待 40 秒、最多三个并发，全部头像暂存不超过 8 MiB。未匹配、无图、超时或普通失败保留演员姓名，不阻止影片完成；头像提交得到确认后才写入 NFO 相对引用。人物可选简介超出 NFO 预算时舍弃可选字段并记原因，完整影片简介和演员姓名不截断。显式重刮生成新的头像名，旧图保留；重试复用已经核实的头像，不重复生成。

MetaTube 搜索先过滤同号候选，保持后端来源顺序，逐个尝试可用详情；HTTP 404、番号或身份不符尝试下一同号来源。搜索、详情的连接中断、超时、HTTP 429／5xx 最多再试一次，详情先尝试其它同号来源再重试；停止可以取消请求和等待。同一任务同号分段采用已经选定的资料源。网络请求不跟随重定向，不使用系统代理环境；只访问配置后端的固定接口，Token 不写入 URL 或诊断原因。

## 中断、重试和操作记录

结果中的「待核实」表示提交没有取得终态证据，不等于写入失败。页面的失败计数包含待核实项，项目和步骤明细保留实际状态。

点击「重试未完成项」后，后端先查旧回执、上传终态或目标文件当前完整摘要，再按当前文件补缺；不会重放旧覆盖计划。旧任务扫描完整时只处理仍在原目录内的未完成视频；扫描未完成则重新扫描完整范围。扫描前就因核实中断的重试记录仍追溯真正的原任务，继续从最新记录重试也不会丢掉旧步骤。

同一后端轮次内若仍然没有终态证据，结果保持待核实，停止整次任务，不能把「查不到回执」当作失败并换键重复写入。此时可在应用中心重启后端，再点击重试；旧轮次被宿主撤销后核对当前文件并补缺。文件已被手动移成不一致状态时需要你手动核实。目录身份、位置或授权变化，以及记录无法保存时停止整次任务；普通来源／海报失败只记录本项原因并继续下一片，已经完成的步骤保留。

每次任务在私有 SQLite 中记录原目录、完整扫描项目、来源原因、写入步骤及回执，按键集分页读取。保留最近 30 天的记录，在后端初始化或开始新任务时清理过期项，不删除网盘文件。设置和 Token 同库保存并随该应用数据库备份；备份含这些秘密，按宿主备份策略保护。新版不迁移或查看旧版宿主刮削记录和页面存储。

## 构建和本地核验

环境为 Node.js 22.22.0、Rust 1.99 系列构建镜像及 Docker。根目录运行下面命令，输出必须是仓库外的新目录。

```bash
npm ci
PATH="$HOME/.cargo/bin:$PATH" CARGO_TARGET_DIR=/tmp/tgdrive-app-scraper-target \
  npm run build:media-scraper -- /tmp/media-scraper-packages-new
```

入口 `tools-v1/build-media-scraper.mjs` 与影视共用 `tools-v1/build-backend-app.mjs`：页面编译一次，两目标在对应 Docker 架构中用 musl 静态构建，冻结 Rust 源码，收集原始许可，实际打包 ZIP 并执行 `tgapp elf` 和 `tgapp verify`。联网采用 rustls，无系统 OpenSSL 依赖。可追加两个已构建原生目录（先 amd64 后 arm64）重复打包；仍核对原生身份、目标和真实 ELF。相同编译后文件应逐字节一致；已发布的同版本同目标包不得替换，修复应升版本。

真实页面测试入口如下，需要已安装的 Playwright Chromium 无头浏览器（可用 `npx playwright install chromium --only-shell` 安装）；必要时用 `TGDRIVE_BROWSER_EXECUTABLE` 明确指定本地浏览器。它编译真实页面入口，在不透明沙箱 iframe 中加载契约 CSP，使用共享 Rust 测试替身和页面假后端，覆盖桌面／手机、浅色／深色，以及选择授权、开始停止、分页、设置、关闭页面不停和重开观察。默认截图输出到新的临时目录；可在 `--` 后传新的截图目录，已存在的目录会被拒绝。该独立入口不进入默认单测或应用包，不使用真实宿主或生产数据。

```bash
PATH="$HOME/.cargo/bin:$PATH" CARGO_TARGET_DIR=/tmp/tgdrive-app-scraper-target \
  cargo build --locked -p tgdrive-test-host --bin tgdrive-test-worker
CARGO_TARGET_DIR=/tmp/tgdrive-app-scraper-target npm run test:media-scraper:browser
```

Linux 原生探测使用 `tools-v1/native/media-scraper-probe.mjs`，通过只读、断网容器运行。它以 UID 65534 实际启动后端，核对内部就绪、主人接口、外部与内部前缀拒绝、后台活动续期、SIGTERM 后长扫描连接回收、监听关闭和退出码 0，以及数据库重开后任务中断而不续跑；本应用不创建操作系统子进程。假宿主不会给视频或写入能力，MetaTube 地址为本地未监听端口，不连接真实 MetaTube 或 Telegram。先按上述入口构建两架构，再在仓库根目录运行：

```bash
for arch in amd64 arm64; do
  docker run --rm --network none --platform "linux/$arch" --entrypoint node \
    --mount "type=bind,source=$PWD,target=/src,readonly" \
    --mount "type=bind,source=/tmp/media-scraper-packages-new/native-linux-$arch,target=/native,readonly" \
    "app-native-builder:$arch" \
    /src/tools-v1/native/media-scraper-probe.mjs /native/backend/app /src/media-scraper/app.json
done
```

原生构建和许可收集规则见 [应用开发指南](../docs/app-development.md)。

## 范围与许可

本应用仅处理 MetaTube 番号影片，不提供外部 HTTP 服务、删除入口、宿主内置刮削服务或旧记录迁移。受单目录 32 MiB 元数据预算、同基本名最多 128 个视频和条件移动事务最多 64 个操作约束，超过时明确拒绝该项，不静默截断或部分移动。

自动化测试和两架构容器探测只覆盖合成网盘与本地假服务，没有验证真实 MetaTube 可用性、真实 Telegram 读写、正式宿主的全部硬隔离、官方影视客户端消费或 Safari／Firefox。NFO 的生成与解析规则有回归，但不据此声称官方客户端实测通过。
